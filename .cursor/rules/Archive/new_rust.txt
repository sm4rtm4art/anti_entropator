# Rust Standards

Work in small, testable increments. Search existing modules before adding new
abstractions, and prefer local patterns over new helper layers.

## Error Handling

- Treat filesystem, object-store, catalog, and subprocess operations as fallible.
- Avoid `.unwrap()` and `.expect()` in production I/O paths.
- Use `anyhow` in CLI orchestration when contextual errors help operators.
- Prefer typed errors in library-style modules when they clarify domain failure
  modes or improve testability.

## Boundaries

- Keep domain logic separate from execution where practical.
- Prefer typed domain values over passing raw `String` or `PathBuf` through many
  layers without validation.
- Route object-store operations through the OpenDAL boundary unless a specific
  lower-level integration requires otherwise.
- Treat catalog/object-store consistency as a correctness concern, not only as
  logging or best-effort cleanup.

## Testing And Validation

- Add focused tests for pure logic and error-prone boundary behavior.
- Prefer deterministic tests over tests that depend on local machine state.
- Use container-backed integration tests for Lakekeeper/RustFS behavior when the
  feature crosses catalog or object-store boundaries.
- During iteration, run targeted checks first; reserve full validation for
  milestone or release preparation.
