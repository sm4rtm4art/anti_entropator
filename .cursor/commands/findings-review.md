# Findings review

Review the requested change (diff, branch, or files) and report findings first.

1. List findings numbered, sorted High, Medium, Low.
2. For each: impact, location (code reference), why it matters, suggested fix.
3. Use evidence from code, tests, or docs. Drop findings you cannot support.
4. If there are no findings, say so and name residual risks and test gaps.
5. End with a short conclusion: confidence, required fixes, next step.

Format:

```text
## Findings

### 1. High: <headline>
<impact, location, fix>

## Conclusion
<confidence, required fixes, next step>
```
